# SEQRET Product Requirements Document v2

## 문서 역할

이 문서는 SEQRET이 해결할 문제, 대상 고객, 핵심 제품 규칙, 구현 우선순위와 기능별 수락 기준을 정의한다.

## 제품 정의

### 제품명

> 짐확정 — 소규모 이사의 쌍방 확인 견적서

### 한 줄 정의

> 방을 약 60초 촬영하면 AI가 이삿짐과 확인할 작업조건을 정리하고, 소비자와 이사업체가 “이 가격에 어디까지 옮기기로 했는지” 한 장으로 함께 확인한 뒤 당일 변경도 다시 승인하는 서비스

### 해결할 문제

방문 견적 없이 전화·메신저·사진으로 계약하는 소규모 이사는 짐, 작업조건, 포함 범위와 금액이 여러 대화에 흩어진다. 이 때문에 소비자, 상담자와 현장기사가 서로 다른 범위를 기준으로 이사를 시작하고, 당일 누락이나 추가비용이 발생해도 최초 확인 범위와 새로 발생한 작업을 구분하기 어렵다.

한국소비자원에 따르면 2025년 이사서비스 피해구제는 961건이었고, 소규모 이사 계약 241건의 65.1%가 20~30대였다. 피해 유형은 물품 파손·분실 47.7%, 추가비용 요구 24.9% 순이었다. 85만 원 계약 후 이사 당일 50만 원을 추가 요구하고, 소비자가 거부하자 작업을 중단한 사례도 확인됐다. [한국소비자원 소규모 이사 피해예방주의보](https://www.kca.go.kr/home/sub.do?menukey=4005&mode=view&no=1004458186)

SEQRET은 적정가격이나 책임을 판정하지 않는다. 계약 전 확인 범위와 현장 변경을 분리하고, 변경 작업과 금액에 소비자가 명시적으로 응답할 수 있게 한다.

### 대상 고객

#### 초기 사용자

서울·수도권에서 원룸·투룸 규모의 비대면 견적 이사를 준비하는 20~30대 1인 가구 소비자다.

- 이사업체를 이미 선택했거나 한 업체와 견적을 협의 중이다.
- 방문 견적 없이 사진·영상과 설명으로 짐을 전달한다.
- 포함 범위와 총액을 한눈에 확인하기 어렵다.
- 이사 당일 추가 작업과 금액에 현장에서 응답해야 할 수 있다.

#### 거래 참여자

| 역할 | 핵심 과업 | 권한 경계 |
| --- | --- | --- |
| 소비자 | 짐 초안을 검수하고 업체 제안과 당일 변경에 응답한다. | 업체의 차량·인력 운영과 작업 가능 여부를 결정하지 않는다. |
| 업체 담당자 | 작업범위와 조건을 검토해 포함·제외 작업과 총액을 제안한다. | 소비자 대신 확인하거나 변경을 승인하지 않는다. |
| 현장기사 | 최신 승인본을 확인하고 현장 차이를 증거와 함께 보고한다. | 변경 금액이나 소비자 승인을 확정하지 않는다. |

#### 구매 고객

초기 구매 고객은 반복 상담, 현장 재협상, 작업 중단과 사후 민원 비용을 줄이려는 소형 이사업체다. 이사 플랫폼은 공동확인 흐름이 검증된 뒤의 확장 고객이다.

| 구매 고객 | 구매 이유 | 검증 기준 |
| --- | --- | --- |
| 소형 이사업체 | 상담 내용을 현장에 정확히 인계하고 누락·추가금 설명·작업 불발 비용을 줄인다. | 실제 상담 건 도입 의사, 지불 방식과 거절 이유 확인 |
| 이사 플랫폼 | 중개 이후 범위 오해와 추가금 민원을 줄이고 거래 기록을 표준화한다. | 기존 견적·배정 흐름과의 연동 의사 확인 |

소비자는 무료로 참여하고 업체가 거래 관리 기능의 비용을 부담하는 모델을 우선 검증한다.

#### 대상이 아닌 사용자

- 여러 업체의 가격 비교나 추천이 필요한 사용자
- 사무실·해외·셀프 이사 사용자
- 결제, 보험, 전자계약 또는 법적 분쟁 판단이 필요한 사용자

### 핵심 결과물

제품의 대표 결과물은 AI 견적이나 추천 목록이 아니라 하나의 `공동확인 카드`다.

공동확인 카드는 다음 내용을 함께 보여준다.

- 작업범위 버전과 생성 시각
- 출발지·도착지와 구역별 짐 항목
- 수량·분해·설치·운반 주의사항을 포함한 항목 설명
- 확인이 필요한 작업조건
- 포함 작업과 제외 작업
- 기본금액, 조정 사유·금액과 총액
- 소비자와 업체의 확인 상태와 시각
- 이전 승인본, 변경 사유와 변경 전후 총액

카드는 전자계약서나 책임 인정 문서가 아니다. 양측이 같은 작업범위와 금액을 확인했다는 거래 기록이다.

### 가치와 차별화

SEQRET은 업체 탐색이나 예상가격 산정이 아니라 업체 선택 이후의 거래 실행 구간을 다룬다.

| 경쟁 방식 | 기존 가치 | SEQRET의 차이 |
| --- | --- | --- |
| 견적 비교 플랫폼 | 업체 탐색과 가격 비교 | 선택한 한 업체와 범위·금액·변경 이력을 관리한다. |
| 사진·영상 AI 견적 | 입력 편의와 예상가격 | AI 결과를 쌍방이 검토할 작업범위 초안으로 사용한다. |
| 전화·메신저 | 빠른 상담과 자료 공유 | 최신 승인본과 변경 전후를 하나의 버전 구조로 남긴다. |
| 방문견적·계약서 | 상세한 사전 확인 | 비대면 소규모 이사에서 당일 변경까지 같은 흐름으로 확인한다. |
| 업체 운영도구 | 배차·인력·일정 관리 | 소비자와 현장기사까지 같은 승인본을 보게 한다. |

방어 가능한 핵심은 `AI 초안 → 업체 제안 → 동일 버전 쌍방 확인 → 현장 변경 재승인`이 하나의 거래 이력으로 이어지는 구조다.

## MVP 목표와 성공 정의

### 핵심 가설

> AI가 촬영 자료를 검토 가능한 작업범위 초안으로 바꾸고, 소비자와 업체가 같은 버전과 총액을 확인하면 비대면 견적의 입력 부담과 범위 오해를 함께 줄일 수 있다.

AI는 핵심 입력 방식이다. 수동 입력은 분석 실패나 누락을 보완하는 복구 수단이며, AI의 제품 가치를 대체하는 별도 핵심 흐름이 아니다.

### 제품 성공 기준

| 지표 | 기준 | 의미 |
| --- | ---: | --- |
| AI 초안 작성 시간 | 동일 목록 수동 작성보다 짧음 | 촬영이 입력 비용을 줄인다. |
| AI 초안 검수 완료율 | 80% 이상 | 사용자가 결과를 이해하고 업체 전달 범위로 만든다. |
| 치명적 누락 | 수동 입력보다 많지 않음 | 시간 단축을 위해 중요한 정확성을 희생하지 않는다. |
| 동일 버전 공동확인 완료율 | 80% 이상 | 양측이 같은 범위와 총액을 확인한다. |
| 버전·금액 오인 | 사용자 테스트 0건 | 서로 다른 내용을 승인했다고 믿지 않는다. |
| 현장 변경 처리 | 제시된 테스트 시나리오 100% 완료 | 변경 제안이 소비자 응답과 결과 버전까지 이어진다. |
| 업체 도입 의사 | 인터뷰 업체 과반 | 실제 상담 건에 적용할 이유가 있다. |
| 유료 검증 | 조건부 유료 파일럿 3곳 또는 실제 유료 파일럿 1곳 | 구매 주체와 지불 조건을 확인한다. |

## MVP 범위

### P0 핵심 흐름

1. 소비자가 작업을 만들고 이사일, 출발지·도착지와 촬영 구역을 입력한다.
2. 소비자가 방을 약 60초 촬영하거나 사진을 등록한다.
3. AI가 구역별 짐 후보와 확인이 필요한 작업조건을 초안으로 만든다.
4. 소비자가 초안을 수정하고 누락 항목을 추가한다.
5. 소비자가 이미 선택한 업체에 참여 링크를 전달한다.
6. 업체가 작업범위, 포함·제외 작업과 총액을 새 버전으로 제안한다.
7. 소비자와 업체가 같은 버전을 각각 확인한다.
8. 확인된 버전은 잠기고 공동확인 카드로 표시된다.
9. 현장기사는 작업 전에 최신 승인본을 확인한다.
10. 현장 차이가 있으면 기사가 증거를 남기고 업체가 변경 작업·사유·총액을 제안한다.
11. 소비자가 승인·거절·설명 요청으로 응답하며 승인된 변경만 새 버전에 반영된다.

업체가 참여하지 않은 소비자 초안은 승인본이나 공동확인 완료로 표시하지 않는다.

### 우선순위

| 구분 | 범위 |
| --- | --- |
| P0 | 작업 생성, 촬영·업로드, AI 초안과 수동 보정, 업체 초대·제안, 동일 버전 공동확인, 공동확인 카드, 기사 승인본 열람, 현장 이슈·변경 제안·소비자 응답, 버전 이력 |
| P1 | 구조화된 수량·작업 옵션, 출발지·도착지 작업조건, 촬영 품질 안내, 버전 차이 비교, 완료 미디어·완료 확인, PDF, 외부 알림 |
| P2 | 전후 영상의 파손 의심 지점 표시, 업체 운영 통계, 이사 플랫폼 API 연동 |
| 제외 | 자동 가격·적정가격 판정, 자동 파손·책임 판정, 전자서명, 결제·에스크로, 업체 추천·견적 비교, 보험·분쟁 중재 |

P1은 현재 작업범위 설명과 포함·제외 항목으로 처리하는 정보를 구조화해 정확도와 검수 속도를 높인다. 기존 승인본과 변경 이력의 의미는 유지한다.

## 제품 상태와 핵심 규칙

### 공통 용어

| 용어 | 의미 |
| --- | --- |
| AI 초안 | 촬영 자료에서 생성됐으며 소비자 검수가 필요한 짐과 확인 항목 |
| 소비자 초안 | 소비자가 수정 중이며 업체가 아직 제안하지 않은 버전 |
| 업체 제안 | 업체가 범위, 포함·제외 작업과 금액을 붙여 보낸 버전 |
| 승인본 | 소비자와 업체가 같은 버전을 각각 확인해 더 이상 수정할 수 없는 범위와 금액 |
| 공동확인 카드 | 현재 업체 제안 또는 승인본을 한 화면에 보여주는 결과물 |
| 현장 이슈 | 현장기사가 승인본과 다른 사실을 증거와 함께 보고한 기록 |
| 변경 제안 | 업체가 현장 이슈를 기준으로 제안한 변경 작업과 금액 |

### 버전과 공동확인

- 모든 제안은 버전 ID, 작성자, 생성시각과 기준 버전을 가진다.
- 소비자와 업체가 같은 버전에 각각 확인해야 승인본이 된다.
- 범위나 금액이 바뀌면 새 버전을 만들고 다시 확인한다.
- 승인본은 덮어쓰지 않으며 새 제안과 구분해 열람할 수 있어야 한다.
- 확인은 내용 확인 기록이며 전자서명, 결제 또는 책임 인정이 아니다.

### AI 초안

- AI는 구역별 가구·가전·박스와 확인이 필요한 작업조건을 제안한다.
- 확인 가능한 수량, 분해·설치 여부와 운반 주의사항은 항목 설명에 포함한다.
- 영상으로 확정하기 어려운 엘리베이터, 계단, 주차, 사다리차와 운반거리는 확인 필요로 표시한다.
- 신뢰도가 낮은 항목은 자동 확정하지 않고 근거 미디어와 함께 검수를 요구한다.
- AI는 가격, 차량, 인원, 파손, 책임 또는 계약 효력을 결정하지 않는다.
- 재분석은 사용자가 수정한 값을 동의 없이 되돌리지 않는다.

### 현장 변경

- 현장 이슈는 기준 승인본, 사유, 설명과 증거를 가진다.
- 업체만 변경 작업과 금액을 제안하고 소비자만 이에 응답한다.
- 소비자는 기존 총액과 변경 후 총액을 함께 확인한다.
- 승인된 변경만 새 버전과 총액에 반영된다.
- 거절과 설명 요청은 기존 승인본을 바꾸지 않는다.

### 접근과 개인정보

- 역할 링크는 한 작업과 한 역할의 접근만 허용한다.
- 집 내부 미디어는 허용된 역할에만 제한된 시간 동안 제공한다.
- 만료·폐기·재발급된 링크의 권한은 서로 섞이지 않는다.
- 미디어 수집 전에 이용 목적, 보관기간과 삭제 방법을 안내한다.
- 역할 링크는 신원 인증이나 전자서명을 대신하지 않는다.

## 기능 요구사항과 수락 기준

### 작업 생성과 참여

| 요구사항 | 수락 기준 |
| --- | --- |
| 소비자가 작업을 만든다. | 이사일, 출발지·도착지와 촬영 구역이 저장되고 재접속 후 유지된다. |
| 소비자가 업체를 초대한다. | 업체 참여 전에는 소비자 초안이며 승인본으로 표시되지 않는다. |
| 업체가 현장기사를 초대한다. | 기사는 최신 승인본과 허용된 현장 행동에만 접근한다. |
| 역할 링크를 폐기·재발급한다. | 만료·폐기된 링크는 접근할 수 없고 새 링크와 권한이 섞이지 않는다. |

### 촬영과 AI 초안

| 요구사항 | 수락 기준 |
| --- | --- |
| 소비자가 구역별 미디어를 등록한다. | 모바일에서 업로드하고 처리 상태를 재접속 후에도 확인한다. |
| AI가 짐과 확인 항목을 비동기로 만든다. | 분석 중·완료·실패를 구분하고 검수 전에는 업체 제안이나 승인본으로 표시하지 않는다. |
| 결과의 근거와 불확실성을 표시한다. | 사용자가 항목의 출처 구간을 확인하고 낮은 신뢰도 항목을 구분한다. |
| 소비자가 결과를 보정한다. | 항목을 수정·삭제·추가하고 수정값을 유지한 채 업체에 전달한다. |
| 분석 실패를 복구한다. | 이미 성공한 입력을 잃지 않고 재시도하거나 수동으로 P0 흐름을 계속한다. |

## 출시 차단 조건

다음 중 하나라도 발생하면 P0를 완료로 판단하지 않는다.

- AI 실패 후 기존 입력을 유지한 채 공동확인 흐름을 계속할 수 없다.
- 서로 다른 버전의 확인으로 승인본이 만들어진다.
- 승인본의 범위나 총액이 같은 버전에서 변경된다.
- 공동확인 카드에서 포함·제외 작업, 총액 또는 양측 상태를 확인할 수 없다.
- 기사가 승인본이 아닌 버전을 현재 합의로 본다.
- 소비자가 승인하지 않은 현장 변경이 범위나 총액에 반영된다.
- 다른 작업 또는 역할의 비공개 미디어에 접근할 수 있다.
- AI나 완료 화면이 가격, 파손, 책임 또는 법적 효력을 확정한다.

## 표현 원칙

제품은 “이 가격에 어디까지 옮기기로 했는지 함께 확인하고 변경을 다시 승인한다”고 설명한다.

다음 표현은 사용하지 않는다.

- 추가금이나 분쟁이 발생하지 않는다.
- AI가 모든 짐과 작업조건을 정확히 찾는다.
- AI가 적정 이사 가격을 계산한다.
- 공동확인 카드가 전자계약서나 전자서명과 같은 법적 효력을 가진다.
- 전후 영상만으로 파손 여부나 책임을 판정한다.
