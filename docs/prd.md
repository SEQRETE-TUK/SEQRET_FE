# SEQRET Product Requirements Document

## 문서 역할

이 문서는 SEQRET이 해결할 문제, 대상 사용자, 제품 규칙, MVP 범위와 기능별 수락 기준을 정의하는 최상위 제품 기준이다.

- 제품의 목적과 우선순위가 충돌하면 이 문서를 우선한다.
- 실제 HTTP 요청·응답은 [API 연동 규격](api-spec.md)과 검증된 백엔드 OpenAPI를 따른다.
- 기술 구현 방식은 [아키텍처](architecture.md)와 [기술 스택](tech-stack.md)을 따른다.
- UI 표현 규칙은 [디자인 시스템](design-system.md)을 따른다.
- 경쟁 근거와 검증 계획은 [리서치](research.md)를 따른다.
- 화면이 존재하거나 예시 데이터로 동작하는 상태는 구현 완료가 아니다. 수락 기준과 실제 서버 연동을 모두 충족해야 한다.

## 제품 정의

### 한 줄 정의

> 소비자·이사업체·현장기사가 같은 작업범위 버전과 금액을 확인하고, 이사 당일 변경도 기존 합의를 덮어쓰지 않은 채 다시 승인하는 공동 기록 도구

### 해결할 문제

이사 계약 전 짐, 작업조건, 포함 범위와 금액은 전화·메신저·사진에 흩어지기 쉽다. 그 결과 세 역할이 서로 다른 정보를 기준으로 행동할 수 있다.

- 소비자는 계약금액에 포함된 작업을 현장에서 즉시 확인하기 어렵다.
- 업체는 누락된 짐과 접근조건 때문에 차량·인력·작업 계획을 다시 세워야 한다.
- 현장기사는 상담 단계에서 합의된 최신 범위를 전달받지 못할 수 있다.
- 당일 변경의 사유, 증거, 증감액과 승인 여부가 구두나 서로 다른 대화방에 남는다.
- 사후에는 최초 합의와 현장 변경을 하나의 흐름으로 재구성하기 어렵다.

SEQRET은 추가비용 자체를 금지하지 않는다. 합의한 범위와 현장에서 달라진 범위를 구분하고, 변경 작업과 금액을 명시적으로 다시 확인하도록 만드는 것이 목적이다.

### 대상 사용자

1차 대상은 국내 주거 이사를 이사업체에 맡기며, 업체를 선택했지만 작업범위와 최종 금액을 확정하기 전인 성인 소비자다.

| 역할 | 핵심 과업 | 권한 경계 |
| --- | --- | --- |
| 소비자 | 짐과 현장조건을 전달하고 범위·총액·당일 변경에 응답한다. | 업체 제안을 확인하고 변경을 승인·거절하지만 업체의 작업 계획을 대신 확정하지 않는다. |
| 업체 담당자 | 고객 정보를 검토해 실행 가능한 작업범위와 금액을 제안하고 같은 버전을 확인한다. | 소비자 대신 확인하거나 현장기사에게 소비자 승인 권한을 부여하지 않는다. |
| 현장기사 | 작업 전에 승인본을 확인하고 현장 차이를 증거와 함께 보고한다. | 금액과 소비자 승인을 대신 확정하지 않는다. |

다음 사용자는 MVP 대상이 아니다.

- 이사업체 추천이나 여러 업체의 견적 비교가 필요한 사용자
- 사무실·해외·셀프 이사 사용자
- 전자계약, 결제, 보험 또는 법적 분쟁 판단을 원하는 사용자

### 가치와 차별화 가설

사진·영상 기반 AI 견적 자체는 이미 경쟁 서비스가 제공한다. SEQRET이 검증할 차별점은 다음 조합이다.

- 업체 선택 이후 한 거래의 작업범위를 소비자가 시작한다.
- 소비자·업체·현장기사가 동일한 최신 승인본을 본다.
- 확인된 버전을 덮어쓰지 않고 변경 이력을 남긴다.
- 당일 추가 작업은 기준 버전, 사유, 증거, 증감액과 응답 상태를 가진다.

이 내용은 검증 전 가설이다. 경쟁우위나 분쟁 감소 효과가 입증됐다고 표현하지 않는다.

## MVP 목표와 성공 정의

### 핵심 가설

> 작업범위와 금액을 버전 단위로 공동확인하고 현장 변경을 같은 흐름에서 재승인하면, 세 역할이 현재 합의와 다음 행동을 별도 설명 없이 이해할 수 있다.

AI 영상 분석은 공동확인 흐름의 입력 비용을 줄이는 보조 가설이다. AI가 실패하거나 효과가 없더라도 사용자가 직접 입력해 핵심 흐름을 완료할 수 있어야 한다.

### 제품 성공 기준

| 지표 | 1차 기준 | 의미 |
| --- | ---: | --- |
| 역할별 핵심 과업 성공률 | 90% 이상 | 도움 없이 자신의 다음 행동을 완료한다. |
| 같은 버전 공동확인 완료율 | 80% 이상 | 업체가 검토한 작업에서 소비자와 업체가 동일 버전을 확인한다. |
| 현장 변경 요청·응답 완료율 | 100% | 테스트에서 제시한 변경이 소비자 응답까지 끝난다. |
| 중대한 버전·금액 오해 | 0건 | 다른 버전 또는 금액을 승인했다고 믿는 사례가 없다. |
| AI 치명적 누락 | 수동 입력보다 많지 않음 | 시간 단축을 위해 정확성을 희생하지 않는다. |
| 무단접근·개인정보 사고 | 0건 | 다른 작업·역할의 비공개 정보에 접근하지 못한다. |

이 수치는 첫 검증 라운드를 위한 기준이며 테스트 결과에 맞춰 사후에 낮추지 않는다.

## MVP 범위

### P0 핵심 흐름

1. 소비자가 작업을 만들고 이사일과 출발지·도착지 조건을 입력한다.
2. 소비자가 구역별 짐 목록을 직접 작성하거나 영상·사진에서 생성된 AI 초안을 검수한다.
3. 소비자가 이미 선택한 업체에 역할 링크를 전달한다.
4. 업체가 짐, 작업조건, 포함·제외, 차량·인원과 총액을 검토해 새 버전을 제안한다.
5. 소비자와 업체가 같은 버전을 각각 확인한다.
6. 공동확인된 버전은 잠기며 현장기사가 작업 전에 열람한다.
7. 현장 차이가 생기면 업체 또는 현장기사가 기준 버전, 사유, 증거, 변경 작업과 증감액을 제출한다.
8. 소비자는 승인, 거절, 설명 요청 중 하나로 응답한다.
9. 승인된 변경만 새 작업범위 버전과 새 총액에 반영된다.
10. 버전과 주요 행동은 감사 이력으로 남는다.

업체가 참여하지 않으면 소비자는 짐과 조건을 정리한 단독 초안을 계속 사용할 수 있다. 이 상태는 `업체 미참여·공동확인 전`으로 표시하며 승인본으로 취급하지 않는다.

### 우선순위

| 구분 | 범위 |
| --- | --- |
| P0 | 작업 생성, 조건·짐 입력, AI 초안과 수동 대체, 업체 제안, 동일 버전 공동확인, 기사 승인본 열람, 현장 변경 요청·응답, 버전·감사 이력 |
| P1 | 완료 사진·영상, 소비자·업체 완료 확인, PDF 출력, 외부 알림, 업체 배차·인력 운영, 작업자 체크인·안전 체크 |
| MVP 제외 | 자동 가격·적정가격 판정, 자동 파손·책임 판정, 전자서명, 결제·에스크로, 업체 추천·견적 비교, 보험·분쟁 중재, 네이티브 앱 |

## 제품 상태와 핵심 규칙

### 공통 용어

| 용어 | 의미 |
| --- | --- |
| 초안 | 소비자 또는 업체가 수정 중이며 공동확인되지 않은 버전 |
| 확인 대기 | 한쪽 또는 양쪽의 확인이 필요한 버전 |
| 공동확인 완료 | 소비자와 업체가 동일한 버전을 각각 확인한 상태 |
| 승인본 | 공동확인 완료되어 같은 버전 안에서 수정할 수 없는 작업범위 |
| 변경요청 | 승인본과 달라진 작업·조건·금액에 대한 별도 응답 단위 |

### 버전과 확인

- 모든 작업범위 제안은 버전 ID, 작성자, 생성시각, 부모 버전과 변경 요약을 가진다.
- 소비자와 업체는 같은 버전 ID에 각각 확인해야 한다.
- 한쪽이 내용을 수정하면 새 버전을 만들고 양측 확인을 다시 받는다.
- 공동확인된 버전의 본문과 총액은 같은 버전 안에서 수정하지 않는다.
- 확인은 내용 확인 기록이며 전자서명, 결제 또는 책임 인정으로 표현하지 않는다.

### 현장 변경

- 변경요청은 기준 승인본, 사유, 설명, 변경 작업, 증거, 증감액을 가진다.
- 소비자는 기존 총액과 변경 후 총액을 함께 본다.
- 승인된 변경만 새 버전과 총액에 반영된다.
- 거절·설명 요청·취소는 기존 승인본과 총액을 바꾸지 않는다.
- 현장기사의 보고는 변경 확정이 아니며 소비자의 응답을 대신하지 않는다.
- 서비스 밖에서 이뤄진 구두 동의를 나중에 디지털 승인으로 기록하지 않는다.

### AI

- AI 결과는 사람이 수정하는 초안이다.
- AI는 물품 후보와 불확실한 항목을 제안할 수 있다.
- AI는 가격, 차량, 인원, 접근조건, 파손, 책임 또는 계약 효력을 확정하지 않는다.
- 신뢰도가 낮거나 충돌하는 항목은 자동 확정하지 않는다.
- 재분석은 사용자가 수정한 내용을 명시적 동의 없이 덮어쓰지 않는다.
- AI 실패 시 수동 입력으로 같은 P0 흐름을 끝낼 수 있어야 한다.

### 접근과 개인정보

- 역할 링크는 한 작업과 한 역할의 접근만 허용하며 개인 신원 인증을 대신하지 않는다.
- 역할 링크는 만료·폐기·재발급할 수 있어야 한다.
- 집 내부 미디어는 공개하지 않고 허용된 역할에만 제한 시간 동안 보여준다.
- 촬영 전 얼굴, 신분증, 문서, 가족사진, 주소 라벨과 귀중품이 포함되지 않도록 안내한다.
- 실제 사용자 미디어를 처리하기 전에 동의, 보관기간, 삭제 절차와 법률 검토를 완료한다.

## 기능 요구사항과 수락 기준

### 작업과 참여

| 요구사항 | 수락 기준 |
| --- | --- |
| 소비자는 이사 작업과 기본 정보를 생성한다. | 이사일, 출·도착지, 주거 형태와 필수 조건이 저장되고 다시 열어도 유지된다. |
| 출발지·도착지 조건을 구조화해 입력한다. | 층, 엘리베이터, 계단, 주차·진입, 운반거리 항목이 값 또는 `모름`을 가진다. |
| 계약 전 도착지 영상은 선택 사항이다. | 영상을 올리지 않아도 도착지 조건을 입력하고 업체 검토를 요청할 수 있다. |
| 소비자는 업체 역할 링크를 발급·폐기·재발급한다. | 만료·폐기된 링크는 접근할 수 없고 새 링크와 권한이 섞이지 않는다. |
| 업체는 승인본을 볼 현장기사 링크를 발급한다. | 기사 링크는 승인본 열람과 허용된 현장 행동만 수행한다. |
| 업체가 참여하지 않은 초안은 공동확인 상태와 구분한다. | 업체 확인 전 화면과 공유 결과에 `업체 미참여·공동확인 전`이 표시된다. |

### 짐 목록과 AI 초안

| 요구사항 | 수락 기준 |
| --- | --- |
| 소비자는 구역과 짐의 이름·수량·작업 옵션을 직접 관리한다. | AI 없이도 업체 검토에 필요한 목록을 완성할 수 있다. |
| 미디어에서 구역별 짐 후보와 확인 필요 항목을 비동기로 생성한다. | 분석 중·완료·실패를 구분하며 사용자 확인 전 승인본으로 표시하지 않는다. |
| AI 결과를 수정하고 수정값을 보호한다. | 재분석이 사용자 변경을 명시적 동의 없이 되돌리지 않는다. |
| AI 실패 시 수동 입력으로 전환한다. | 이미 입력하거나 업로드한 성공 데이터를 잃지 않고 P0 흐름을 계속한다. |

### 제안과 공동확인

| 요구사항 | 수락 기준 |
| --- | --- |
| 업체는 범위와 금액을 검토해 제안한다. | 제안에 작성자, 기준 버전, 변경 요약과 원화 총액이 기록된다. |
| 수정 제안은 기존 내용을 덮어쓰지 않고 새 버전을 만든다. | 이전 버전을 다시 열 수 있고 새 버전이 부모 버전을 참조한다. |
| 오래된 버전을 기준으로 제출하면 충돌을 알린다. | 자동 덮어쓰기 없이 최신 버전 새로고침 또는 비교를 요구한다. |
| 소비자와 업체가 같은 버전을 각각 확인한다. | 서로 다른 버전의 확인 두 개로는 공동확인 완료가 되지 않는다. |
| 공동확인 후 승인본을 잠근다. | 같은 버전의 본문·총액 변경을 거절하고 새 버전 생성을 요구한다. |
| 한쪽이 새 버전을 제안하면 양측이 다시 확인한다. | 이전 버전의 확인 기록은 남지만 새 버전의 확인으로 승계되지 않는다. |

### 현장 변경

| 요구사항 | 수락 기준 |
| --- | --- |
| 현장기사는 작업 전 최신 승인본과 총액을 본다. | 기사 화면의 버전 ID와 내용이 소비자·업체의 최신 승인본과 일치한다. |
| 업체 또는 기사는 승인본을 기준으로 변경요청을 만든다. | 기준 버전, 사유, 설명, 변경 작업, 증거와 증감액이 없으면 전송할 수 없다. |
| 소비자는 변경 전후 총액을 비교하고 응답한다. | 승인·거절·설명 요청의 행위자, 상태와 시각이 기록된다. |
| 승인된 변경만 새 버전과 총액에 반영한다. | 결과 버전이 기준 버전과 변경요청 ID를 참조한다. |
| 승인 외 응답은 기존 승인본을 유지한다. | 거절·설명 요청·취소 후 기존 본문, 총액과 확인 기록이 변하지 않는다. |

### 감사와 접근 제어

| 요구사항 | 수락 기준 |
| --- | --- |
| 생성, 제안, 확인, 변경요청·응답과 링크 폐기를 기록한다. | 기록에 작업, 역할, 대상 버전, 발생시각과 추적 정보가 있다. |
| 모든 작업·미디어 요청에서 작업과 역할 권한을 검사한다. | 다른 작업이나 역할의 URL을 조합해도 데이터에 접근할 수 없다. |
| 비공개 미디어는 제한 시간 접근만 허용한다. | 공개 객체 URL이 없고 만료·폐기 후 기존 접근 경로가 동작하지 않는다. |

## 비기능 요구사항

| 영역 | 요구사항 | 수락 기준 |
| --- | --- | --- |
| 개인정보 | 집 내부 미디어와 민감정보를 허용된 역할 외부에 노출하지 않는다. | 공개 접근과 로그·분석 도구에서 주소 원문, 역할 링크와 비공개 미디어가 노출되지 않는다. |
| 링크 보안 | 역할 링크를 만료·폐기·재발급할 수 있다. | 폐기하거나 만료한 링크로 작업과 미디어에 접근할 수 없다. |
| 멱등성 | 제안·확인·변경 응답의 중복 제출을 안전하게 처리한다. | 반복 요청이 중복 버전 또는 중복 금액 반영을 만들지 않는다. |
| 실패 복구 | 업로드·분석 실패가 성공한 입력을 지우지 않는다. | 실패·재접속 후 완료 데이터가 유지된다. |
| 상태 표현 | 다음 행동과 상태를 색상 외 문장으로 전달한다. | 흑백에서도 상태와 다음 행동을 구분할 수 있다. |
| 반응형 | 소비자·기사 모바일과 업체 모바일·데스크톱을 지원한다. | 대표 viewport에서 가로 스크롤 없이 핵심 과업을 끝낸다. |
| 서버 원본 | 설치 여부와 무관하게 최신 승인 상태는 서버를 기준으로 한다. | 재접속과 다른 기기에서 같은 버전·확인 상태가 보인다. |

## 출시 차단 조건

다음 중 하나라도 발생하면 실제 사용자 대상 MVP를 완료로 판단하지 않는다.

- 서로 다른 버전을 확인했는데 공동확인 완료로 표시된다.
- 공동확인된 버전의 본문이나 총액이 같은 버전에서 바뀐다.
- 기준 버전이나 증감액 없이 현장 변경을 승인할 수 있다.
- 승인하지 않은 변경이 새 총액에 반영된다.
- 서비스 밖의 구두 동의가 디지털 승인으로 표시된다.
- 다른 작업 또는 역할의 비공개 미디어에 접근할 수 있다.
- 만료·폐기된 역할 링크가 계속 동작한다.
- AI 실패 시 수동으로 공동확인 흐름을 끝낼 수 없다.
- AI나 완료 화면이 가격·파손·책임 또는 법적 효력을 확정 표현한다.

## 표현 원칙

사용 가능한 표현:

> 합의한 작업범위와 당일 변경을 한곳에 기록해 미합의 현장 추가금을 줄이기 위한 서비스

검증 전에는 다음을 약속하지 않는다.

- 추가금이 절대 발생하지 않는다.
- AI가 모든 짐을 정확히 찾는다.
- 확인 기록이 계약서나 전자서명과 같은 법적 효력을 가진다.
- 사진·영상으로 파손이나 책임을 자동 판정한다.
- 서비스를 사용하면 실제 분쟁이 감소한다.
