# SEQRET 제품 리서치와 MVP 검증 계획

## 문서 해석 원칙

- 공개 페이지에서 확인하지 못한 기능을 실제 서비스에 없다고 단정하지 않는다.
- 경쟁사 홍보 문구와 실제 사용자 경험을 구분한다.
- 제품 가설은 사용자 행동 검증 전까지 사실이나 경쟁우위로 표현하지 않는다.
- 테스트 결과가 기준에 미달해도 통과 기준을 사후에 낮추지 않는다.
- 한 명의 강한 의견보다 반복 행동, 오류의 심각도와 역할별 차이를 우선한다.
- 제품 결정이 바뀌면 [PRD](prd.md)에 반영하고, 이 문서는 그 근거와 결과를 남긴다.

## 경쟁 환경

### 요약

공개 정보 기준으로 SEQRET과 완전히 동일한 국내 서비스는 확인되지 않았다. 그러나 개별 기능은 이미 여러 서비스가 제공한다.

특히 다음 표현은 차별점으로 사용하기 어렵다.

> 영상을 찍으면 AI가 이삿짐을 분석해 추가금을 줄여준다.

사진·영상 기반 AI 견적과 추가금 방지 메시지는 이미 시장에 존재한다. SEQRET의 차별화 가설은 AI가 아니라 `업체 선택 이후의 다자간 작업범위 버전 관리와 현장 변경 재승인`이다.

### 경쟁 분석 시사점

- 마이스마트무브와 내집이사는 사진·영상 기반 AI 견적을 제공하므로 AI 입력 방식만으로 차별화하기 어렵다.
- 모다는 고객 입력, 상담, 배정과 변경 공유를 연결하므로 업무 흐름의 인접 경쟁자로 봐야 한다.
- 영구크린은 방문견적, 계약서와 보상 정책으로 같은 문제를 다른 방식으로 해결한다.
- SEQRET은 업체 선택 이후의 동일 버전 공동확인과 현장 변경 재승인이 실제 참여 가치를 만드는지 검증해야 한다.

### 시장 구조

```text
견적 비교·업체 연결
└─ 짐싸 / 미소 / 숨고 / 위매치다이사

사진·영상 기반 AI 견적
└─ 마이스마트무브 / 내집이사 / 모다·아이사

계약·추가금 보장
└─ 영구크린 및 일부 직영 이사업체

SEQRET의 목표 영역
└─ 업체 선택 이후 공동 작업범위 버전과 현장 변경 승인
```

### 차별화 가설

> 견적을 만들어주는 서비스가 아니라, 견적 이후 소비자·업체·현장기사가 같은 작업범위와 변경 내역을 확인하는 중립적 거래 기록 도구

구체적인 가설:

- 특정 이사업체에 종속되지 않는 소비자 시작형 도구
- 양측이 동일한 버전을 확인해야 승인본이 되는 구조
- 승인본을 덮어쓰지 않는 변경 이력
- 당일 추가 작업과 증감액에 대한 별도 응답
- 현장기사가 상담 결과를 별도 전달 없이 확인하는 흐름

이 조합의 시장성, 참여 의지와 분쟁 감소 효과는 아직 입증되지 않았다.

## 현재 대안과 경쟁 범위

사용자는 새 제품 없이도 다음 방식으로 문제를 해결한다.

| 현재 대안 | 장점 | 한계 가설 |
| --- | --- | --- |
| 전화·대면 상담 | 빠르고 익숙함 | 기록이 분산되고 현장기사 전달 여부를 확인하기 어려움 |
| 카카오톡 대화방 | 사진·대화를 쉽게 공유 | 최신 합의와 변경 전후 금액을 구조적으로 비교하기 어려움 |
| 방문견적·계약서 | 범위와 금액의 공식성이 높음 | 계약 이후 현장 변경을 같은 구조로 갱신하기 어려울 수 있음 |
| 견적 비교 플랫폼 | 업체 탐색과 가격 비교에 유리 | 업체 선택 이후 다자간 실행 범위 관리가 핵심은 아님 |
| 업체 내부 운영도구 | 배차·인력·일정 관리에 유리 | 소비자와 같은 버전을 공동확인하는 중립 도구가 아닐 수 있음 |

첫 테스트에서는 SEQRET 화면 자체의 선호보다 기존 대안으로 돌아가려는 행동과 이유를 함께 관찰한다.

## 검증 전략

첫 검증은 실제 추가금 감소를 증명하는 장기 실험이 아니다. 사용자가 제품의 상태와 다음 행동을 이해하고 핵심 흐름을 완료할 수 있는지 확인한다.

### 1차: 역할별 과업 사용성 테스트

- 소비자 역할 5명
- 업체 상담자 역할 5명
- 현장기사 역할 2명 이상
- 실제 개인정보가 없는 동일한 가상 이사 시나리오
- 원룸과 아파트 중 반복 가능한 1~2개 대표 상황
- 기능을 설명하지 않고 과업만 전달

다섯 개 주거 형태를 한 번씩 시험하면 사용자 차이와 상황 차이를 구분하기 어렵다. 첫 라운드는 같은 상황을 반복하고 핵심 흐름이 안정된 뒤 빌라·복층·단독주택으로 확장한다.

### 2차: AI 초안과 수동 입력 비교

동일한 짐 목록을 두 방식으로 작성한다.

- A: 영상 AI 초안을 검수해 완성
- B: 구조화 체크리스트로 직접 작성

비교 항목:

- 완료 시간 중앙값
- AI 항목 추가·수정·삭제 수
- 차량·인원·가격에 영향을 줄 수 있는 치명적 누락 수
- 실패 뒤 수동 입력으로 복구 가능한지

AI 방식이 더 빨라도 치명적 누락이 늘면 통과로 보지 않는다.

### 3차: 제한된 실제 흐름

가상 테스트를 통과한 뒤에만 실제 또는 현실적으로 재구성한 이사 건에서 업체 참여와 공동확인을 시험한다.

실제 집 내부 미디어를 사용하기 전에 다음을 완료한다.

- 개인정보 안내와 동의
- 역할별 접근권한 검증
- 보관기간과 실제 삭제 실행
- 민감값의 로그·분석 도구 수집 제외
- 법률·보안 검토 책임자 지정

## 핵심 테스트 시나리오

### 계약 전 공동확인

1. 소비자가 작업과 출·도착지 조건을 입력한다.
2. 짐 목록을 직접 또는 AI 초안으로 완성하고 업체를 초대한다.
3. 업체가 누락 한 건과 작업 option 한 건을 수정하고 총액을 제안한다.
4. 소비자가 변경 요약과 총액을 확인한다.
5. 소비자와 업체가 같은 버전을 각각 확인한다.

관찰:

- 자신의 다음 행동을 설명 없이 찾는가?
- 수정 뒤 이전 확인이 유효하지 않은 이유를 이해하는가?
- 현재 버전과 이전 버전을 구분하는가?
- `내용 확인`을 전자서명이나 결제로 오해하지 않는가?

### 현장 변경

1. 현장기사가 작업 전 승인본을 연다.
2. 진행자가 엘리베이터 고장과 추가 장비 비용 상황을 제시한다.
3. 기사가 기준 버전, 사유, 증거, 변경 작업과 증감액을 등록한다.
4. 소비자가 기존·변경 후 총액을 비교하고 설명 요청 뒤 승인 또는 거절한다.
5. 참가자가 이전 버전과 결과 버전을 다시 확인한다.

관찰:

- 사유와 금액을 이해하고 응답하는가?
- 승인 전후 총액을 혼동하지 않는가?
- 거절 시 기존 승인본이 유지됨을 이해하는가?
- 승인된 변경이 새 버전으로 남았음을 찾을 수 있는가?

### 실패와 복구

1. AI 분석 실패 또는 업로드 실패를 제시한다.
2. 이미 입력한 내용을 잃지 않고 수동 입력으로 전환한다.
3. 만료된 업체 링크로 접근한다.
4. 최신 링크로 다시 참여해 공동확인을 끝낸다.

관찰:

- 실패 원인과 보존된 데이터를 이해하는가?
- 복구 행동을 도움 없이 찾는가?
- 만료와 권한 부족을 구분할 필요가 있는가?

## 세션 기록 양식

각 세션에서 다음을 기록한다.

- 참가자 역할과 관련 경험
- 사용한 시나리오와 빌드·버전
- 과업별 성공·실패·도움 여부
- 과업 시작·종료 시각
- 잘못 누른 행동과 복구 여부
- 참가자가 설명한 현재 상태와 다음 행동
- 버전·금액·확인의 의미에 대한 오해
- AI 항목 추가·수정·삭제와 치명적 누락
- 개인정보·역할 링크·신뢰 관련 우려
- 기존 대안으로 돌아가려 한 시점과 이유

선호도 발언보다 실제 행동과 오류를 우선한다.

## 판정

### GO

- 핵심 지표가 사전 기준을 충족한다.
- 서로 다른 버전이나 총액을 확인하는 치명적 오류가 없다.
- AI 실패 시에도 수동 흐름으로 공동확인할 수 있다.
- 역할별 참가자가 확인을 전자서명·결제·책임 판정으로 오해하지 않는다.

### 조건부 개선

- 공동확인은 완료하지만 특정 단계에서 도움이나 시간이 과도하게 필요하다.
- 수동 입력은 성공하지만 AI 초안이 시간이나 누락을 개선하지 못한다.
- 업체 참여는 낮지만 소비자 단독 카드의 전달 가치는 반복해서 확인된다.

실패한 단계만 수정해 같은 시나리오를 다시 테스트한다. AI가 효과가 없으면 AI를 핵심 가치로 설명하지 않고 수동 입력을 기본값으로 전환한다.

### NO-GO 또는 방향 재검토

- 소비자와 업체가 같은 카드를 사용하지 않고 별도 메신저만 선호한다.
- 현장기사가 작업 전 승인본을 열지 않는다.
- 변경요청을 거치지 않고 구두 승인만 반복한다.
- 참가자가 버전, 총액 또는 확인의 의미를 반복해서 잘못 이해한다.
- 역할 링크와 집 내부 미디어 위험을 허용 가능한 수준으로 통제할 수 없다.

## 출처와 추가 조사 과제

현재 비교표는 각 서비스의 공개 홈페이지, 앱 스토어와 안내 자료를 기준으로 작성했다. 실제 사용성, 계약 과정과 내부 기능은 계정 생성 또는 직접 인터뷰 없이 확인하지 않았다.

추가 조사:

- 소비자 5명 이상의 최근 이사 계약·당일 변경 경험 인터뷰
- 이사업체 상담자와 현장기사의 정보 전달 방식 인터뷰
- 경쟁 서비스 가입·견적·계약 흐름 직접 확인
- 추가금 분쟁 사례에서 최초 누락과 당일 변경의 유형 분류
- 역할 링크, 집 내부 미디어와 보관기간에 대한 법률·개인정보 검토
- 업체가 별도 도구에 참여할 유인과 운영 비용 검증
